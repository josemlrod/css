Cinematic Sites of Savannah

How a tour becomes a Booking

A server-rendered React application that collects a reservation, captures an approved PayPal Order, and checks live capacity before creating a Booking.

The rule that shapes the system

A browser return never creates a Booking. Only a server-verified PayPal capture can do that.

02 / Runtime flow

The payment path

The Checkout Attempt carries the reservation through the untrusted browser payment flow.

Collect

The four-step UI gathers date, time, guests, name, and email in React state.

Validate

The action reloads the Tour, validates input with Zod, and calculates price from stored data.

Attempt

Convex stores a pending Checkout Attempt. The app hashes its private access token.

Pay

PayPal SDK v6 opens PayPal or guest card checkout over the confirm step.

Commit

The capture action checks amount, currency, duplicate delivery, and live capacity in a Convex transaction.

Capacity available → create one paid Booking → email its private management link
Capacity consumed → mark the failure → request a refund → email the Booker

03 / Data model

Three records, three jobs

Checkout Attempts hold pre-payment truth. Bookings exist only after verified payment.

convex/tours.ts

Tour

The sellable catalog entry and source of pricing rules.

  • Copy, image, duration, meeting point
  • Price and currency input
  • Allowed times and maximum guests
convex/checkoutAttempts.ts

Checkout Attempt

A time-limited snapshot created before PayPal checkout.

  • Tour, date, time, party, Booker
  • Price snapshot and PayPal Order ID
  • Payment, expiry, and refund state
convex/bookings.ts

Booking

The paid reservation and source for self-service management.

  • Reservation and Booker details
  • PayPal capture and refund IDs
  • Cancellation and refund status

04 / Route ownership

Where each decision lives

/tour/:tourId

Start Checkout

Loads the Tour, renders the stepper, validates submission, and creates a PayPal Order.

/checkout/success/*

Report status

Reads a token-protected Checkout Attempt. It does not create a Booking.

/paypal/capture/* + /paypal/webhook

Finish payment

The capture action handles primary completion. Verified events provide backup completion and recovery paths.

/manage/:bookingId

Cancel and refund

Checks the private token and 24-hour cutoff, then requests a full PayPal refund.

app/lib/email.ts

Communicate

Builds paid, cancellation, capacity-refund, and refund-failure messages for Resend.

convex/*

Persist and coordinate

Owns stored records and the transaction that prevents overselling during concurrent payments.
