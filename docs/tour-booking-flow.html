Core Flow

Tour Booking Flow

Booker selects tour details and opens PayPal or guest card checkout in the booking stepper. This slice creates the PayPal Order but leaves capture and Booking creation to the next migration slice.

Invariant

Return routes never create Bookings. Only checkout.session.completed from the verified webhook can create one.

Entities

Tour

Catalog item with price, capacity, start times, meeting point.

Checkout Attempt

Temporary payment record. Stores selected details, pricing snapshot, paypalOrderId, status, expiry, token hash.

Booking

Paid reservation. Created only after verified payment and capacity re-check. Stores paypalCaptureId, token hash, cancel/refund state.

Booking Communication

Email sent by app for tour details, refund notices, cancellation results, and refund failures. Stripe receipts stay separate.

PayPal Migration State

Payment persistence uses paypalOrderId, paypalCaptureId, and paypalRefundId. New Checkout Attempts now create PayPal Orders from embedded SDK v6 buttons. Capture, Booking creation, webhooks, and refunds move to PayPal in later slices; the old Stripe completion routes remain temporarily but receive no new checkouts.

Checkout Start

1

Booker chooses PayPal or card

paypal-buttons.tsx validates the confirm-step data before posting date, time, guests, name, and email.

2

Checkout Attempt created

saveCheckoutAttempt stores pending status, 30-minute expiry, pricing snapshot, hashed access token.

3

PayPal Order created

The action computes the total from Tour price and guest count, calls createPayPalOrder, and stores paypalOrderId.

4

SDK opens checkout

The action returns the Order ID to SDK v6. PayPal or the guest card form opens over the confirm step without a Stripe redirect.

5

Checkout canceled

Closing the PayPal overlay sends the Booker to /checkout/cancel/:checkoutAttemptId?token=.... This ends the payment flow without creating a Booking.

Payment Received

1

Webhook verified

/stripe/webhook constructs Stripe event using STRIPE_WEBHOOK_SECRET.

2

Attempt reconciled

completeCheckoutAttempt checks amount, currency, idempotency, and current capacity.

3

Booking created

If capacity exists, Booking is inserted with paymentStatus: paid and the attempt becomes paid.

4

Email sent

App sends Booking details and private /manage/:bookingId?token=... link.

Pending or Expired

The token-protected checkout cancel route only displays Checkout Attempt state; it does not cancel a paid Booking. If payment never completes, no Booking exists. During the migration, Stripe checkout.session.expired events still mark legacy attempts expired.

Capacity Race

Checkout Attempts do not reserve capacity. If payment succeeds after capacity fills, webhook code creates no Booking, marks the attempt refund_pending, creates a full Stripe refund, stores the refund ID, and emails the Booker.

Self-Service Cancellation

Manage route requires Booking ID plus raw token. Before the 24-hour cutoff, refund creation must succeed first. Then Booking becomes canceled, capacity releases, and Payment Status becomes refund_pending.

Refund Lifecycle

Stripe refund.updated or charge.refunded webhooks update the matching Booking or Checkout Attempt by stored paypalRefundId. Succeeded means refunded. Failed/canceled means refund_failed and triggers email.

Code Map

convex/schema.ts

Tour, Checkout Attempt, Booking fields and payment status vocabulary.

app/routes/tour-booking.tsx

Validates Booker input, creates a Checkout Attempt and PayPal Order, then returns the Order ID to SDK v6.

app/components/stepper/paypal-buttons.tsx

Loads SDK v6, checks PayPal and card eligibility, starts payment sessions, and handles cancellation.

app/lib/stripe.ts

Creates Checkout Sessions, verifies webhooks, creates refunds.

convex/checkoutAttempts.ts

Completes attempts, checks capacity, handles refund status by the persisted PayPal refund ID.

app/routes/stripe-webhook.ts

Owns verified Stripe event behavior for payment completion, expiry, refund lifecycle.

app/routes/manage-tour.tsx

Validates private token, enforces 24-hour cutoff, starts cancellation refunds.

convex/bookings.ts

Token-scoped Booking lookup and cancellation mutation.

app/lib/email.ts

Booking Communication content and send functions.
